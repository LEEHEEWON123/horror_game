# Horror Escape Game — Design Spec
**Date:** 2026-06-17  
**Engine:** Unity  
**Platform:** Android  
**Reference:** Little Nightmares

---

## 개요

리틀나이트메어 스타일의 2.5D 공포 탈출 게임. 플레이어는 크리쳐를 피해 맵에서 열쇠를 찾고 출구를 탈출한다.

---

## 1. 전체 구조

### 씬 구성
```
Scenes/
├── MainMenu          # 시작 화면
├── Map_01            # MVP 맵 (이후 Map_02, Map_03... 추가)
└── ComingSoon        # 마지막 맵 탈출 후 스플래시
```

### 씬 흐름
```
MainMenu → Map_01 → (탈출 성공) → ComingSoon
                ↑
         (목숨 0개) → Map_01 재시작 (목숨 3개 초기화)
```

### 프로젝트 구조
```
Scripts/
├── Player/
├── Monster/
├── Map/              # 열쇠, 자물쇠, 출구 문
├── UI/               # HUD, 미니맵, 가상 조이스틱
└── GameManager/      # 목숨, 씬 전환, 게임 상태
```

**GameManager**는 DontDestroyOnLoad로 씬 전환 사이에도 상태를 유지한다.

---

## 2. 플레이어 시스템

### 이동
- 가상 조이스틱 입력 → Rigidbody 기반 이동
- X축(좌우) + Z축(앞뒤) 모두 이동 가능 — 리틀나이트메어와 동일한 2.5D 방식
- 카메라는 고정 사이드뷰, 플레이어는 3D 공간에서 이동
- 앞뒤 이동은 좌우보다 살짝 느리게 (원근감 표현)

### 상태 머신
```
Idle → Walk → (크리쳐 접촉) → Die
```

### 목숨 시스템
- 시작 시 목숨 3개
- 크리쳐에 닿으면 목숨 1개 차감 + 현재 맵 시작 위치로 리스폰
- 목숨 0개 → Map_01로 씬 전환 + 목숨 3개 초기화
- 목숨은 맵 이동 시에도 유지 (GameManager 관리)

### 상호작용
- 열쇠 근처에서 상호작용 버튼 → 줍기
- 자물쇠 근처에서 열쇠 보유 중이면 → 잠금 해제
- 출구 문 근처에서 해제된 상태면 → 다음 씬으로 전환

---

## 3. 몬스터 AI

### 행동 사이클
```
Patrol (배회) → [시야 감지] → Chase (추격) → [놓침] → Search (두리번) → Patrol
```

### Patrol
- NavMesh 위에서 웨이포인트 순찰 또는 랜덤 이동
- 느린 속도로 맵을 배회

### 시야 감지
- 몬스터 전방 부채꼴 시야 범위
- Physics.OverlapSphere + 각도 체크로 구현
- 시야 내 플레이어 + 장애물 없음 (Raycast) → Chase 전환

### Chase
- NavMesh Agent로 플레이어 실시간 추적
- Patrol보다 빠른 속도 (달리기)
- 플레이어에 닿으면 → 플레이어 사망 처리

### Search
- 플레이어가 시야에서 벗어나면 마지막 목격 위치로 이동
- 일정 시간 두리번거리다 Patrol로 복귀

### 배치
- 맵당 크리쳐 1종, 여러 마리 동시 소환 (턴제 아님)
- MVP(Map_01) 기준 크리쳐 1종 디자인

## 4. 맵 / 열쇠 / 자물쇠 시스템

### 오브젝트 구성
```
맵 안에 존재:
├── Key (열쇠)        — 줍기 가능, 1개
├── Lock (자물쇠)     — 열쇠로 해제
└── ExitDoor (출구)   — 자물쇠 해제 후 통과 가능
```

### 흐름
```
열쇠 줍기 → 자물쇠 해제 → 출구 문 활성화 → 탈출
```

### 미니맵 표시
- HUD 우상단에 항상 표시
- 아이콘:
  - 열쇠 — 미수집 시만 표시
  - 자물쇠 — 해제 전까지 표시
  - 출구 문 — 항상 표시
  - 플레이어 위치 — 항상 표시
- **몬스터 위치는 미니맵에 표시 안 함** (긴장감 유지)

### 맵 간 이동 (확장 시)
- 각 맵의 열쇠는 해당 맵 자물쇠에만 사용
- MVP는 1맵이므로 단순 구조

## 5. UI / HUD

### 화면 레이아웃
```
┌─────────────────────────────┐
│ ❤️❤️❤️        [미니맵]      │
│                              │
│       [게임 화면]            │
│                              │
│  [조이스틱]      [상호작용]  │
└─────────────────────────────┘
```

### 요소별 상세
- **목숨 표시** — 좌상단, 하트 아이콘 3개
- **미니맵** — 우상단, 소형 맵
- **가상 조이스틱** — 좌하단, 터치 시 나타나는 다이나믹 조이스틱
- **상호작용 버튼** — 우하단, 열쇠/자물쇠/출구 근처에서만 활성화
- **열쇠 보유 표시** — 상호작용 버튼 옆에 작게 표시

### 씬 전환 연출
- 사망 시 — 페이드 아웃 → 리스폰
- 맵 탈출 시 — 페이드 아웃 → ComingSoon 씬
- 게임 시작 — 페이드 인

## 6. 게임 상태 관리

### GameManager (DontDestroyOnLoad)
```
관리 데이터:
├── 목숨 수 (int, 0~3)
├── 현재 맵 번호 (int)
└── 열쇠 보유 여부 (bool)
```

### 상태 흐름
```
게임 시작 → 목숨 3, Map_01 로드

플레이 중
→ 피격 시 목숨 -1, 현재 맵 리스폰
→ 목숨 0 → Map_01 씬 전환 + 전체 초기화

탈출 성공
→ ComingSoon 씬 전환
→ "추가 맵 업데이트 예정" 스플래시 + 메인메뉴 버튼
```

### 씬 간 데이터 유지
- GameManager만 DontDestroyOnLoad
- 열쇠는 맵마다 독립 (씬 로드 시 초기화)
- 목숨만 씬 넘어도 유지
